# Top Rail Research — Grafana vs LiteLLM

Full detail and citations: [`grafana.md`](./grafana.md), [`litellm.md`](./litellm.md).
Screenshots and provenance: [`reference/manifest.md`](./reference/manifest.md).

| #   | Dimension              | Grafana                                                                                                                                                                                                                                                                                                                                        | LiteLLM                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Top bar contents       | Nav toggle + logo (only when menu undocked), breadcrumb trail, fake-search/command-palette box (⌘K), quick-add, help, extension-sidebar icon, sign-in/avatar. Org switcher lives in the side rail's own head, not the top bar, and renders nothing at all on a single-org instance.                                                            | **Current source**: breadcrumb (title-only) plus gateway/agent view switcher on the left; docs/blog/community/theme-toggle/notifications on the right; no logo, no nav toggle, no user menu. **Screenshot-verified generation**: a fuller bar with logo, dark-mode toggle, version badge, docs/blog/socials, notification bell, and an account pill, closer to Grafana's shape, but an earlier point in the same modern rewrite, not the latest. |
| 2   | Identity surface       | Avatar-only (24px gravatar) in the top bar; click opens a dropdown (theme, kiosk mode, blog, plugin slots, sign out). No name/role shown at rest.                                                                                                                                                                                              | **Current source**: moved out of the top bar entirely into the sidebar footer: a 30px colour-hashed initials avatar (no photo), name+role when expanded, click opens a rich popover (tier/role/email/user-ID with copy buttons, feature toggles, logout). **Screenshot-verified generation**: a simple top-bar "Account ▾" pill/avatar dropdown instead.                                                                                         |
| 3   | Nav-collapse toggle    | State-dependent: top bar (next to logo) when the mega menu is closed or open-as-overlay; moves to the **rail's own head** when docked. Just changed via PR `#129580` (merged 12 Aug 2026), which unified a previously-inconsistent hamburger position.                                                                                         | **Current source**: lives only on the **sidebar's own head** (`PanelLeftClose/Open`), never in the top bar. **Screenshot-verified generation**: a hamburger sat in the top bar instead, the same top-bar-toggle-to-rail-head-toggle move, independently confirmed, not yet visible in any available screenshot of the very latest state.                                                                                                         |
| 4   | Breadcrumbs in top bar | Yes: a genuine multi-level hierarchical trail (e.g. `Dashboards › Demo: Prometheus › kube-state-metrics - Home`), explicitly the headline feature of the 2022-23 redesign. Coexists with a separate page-body title block; breadcrumb is hierarchy/wayfinding, page header is page identity.                                                   | Yes, but minimal: a single current-page **title only** (the trail's "section" half is discarded at render time), paired with a mode switcher. No separate page-body breadcrumb/title component; each page hand-builds its own heading.                                                                                                                                                                                                           |
| 5   | Page-level header      | Separate, chrome-owned `PageHeader` component (`<h1>` plus optional icon/subtitle plus right-aligned actions) for Standard/Home layout pages; dashboards (Canvas layout) skip it and use their own dashboard-specific header instead.                                                                                                          | No shared component: every page renders its own title/description/action-button block in the scrollable body. Some pages (e.g. Usage) add a second sub-toolbar row for view controls, also in the body, not the sticky chrome.                                                                                                                                                                                                                   |
| 6   | Content width          | **No max-width** on dashboards (Canvas) or ordinary pages (Standard), confirmed in source. The **one exception** is the Home landing page, explicitly capped at 1440px and centred. Live 1280px captures show edge-to-edge content; no wide (2560px+) unobscured capture was obtained, so the wide-viewport claim rests on source, not pixels. | **No max-width** anywhere in the shell layer (confirmed in source); content simply fills whatever remains after the sidebar. Corroborated live at 2590-3403px: forms, tables and chat panes all run to within a few px of the canvas edge, no unused gutter, a direct contrast with the pre-rewrite UI, which left a large empty right margin at similar widths.                                                                                 |
| 7   | Sticky behaviour       | Top nav is `position: fixed`; **both** header rows (breadcrumb row, and the actions/time-picker row when present) are pinned inside it. Docked mega menu is also fixed. Content gets top-padding to compensate.                                                                                                                                | Architectural, not CSS-sticky: the viewport itself never scrolls (`h-screen overflow-hidden`); only the content `<main>` has `overflow-y-auto`, so the sidebar and header simply sit outside the scrolling region. Per-page sub-toolbars (e.g. Usage's view-selector row) are NOT pinned and scroll away with the content.                                                                                                                       |
